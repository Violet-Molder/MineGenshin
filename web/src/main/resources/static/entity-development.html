实体开发文档

从零写一个实体：注册 → 实体类 → 属性 → 生成 → AI → 同步 → 渲染。所有路径与示例都取自当前代码（1.0.1）。

AI 部分本文只给"怎么选、怎么挂"，Goal 与 Brain 的完整原理见 实体 AI 深入指南（1500+ 行，含原版 Goal 全清单）。

1. 实体在项目里的位置

目录放什么现有例子
content/entities/实体注册表 ModEntities 与实体基类ModEntities.java
content/entities/teyvat/提瓦特生物（怪物、Boss、召唤物）monster/slime/LargeCryoSlime、skill/vesna/VesnaAttackProjectile
content/entities/area/领域型实体（范围效果、场地）TalismanSpiritArea、ThunderCloudEntity、StellarVortexEntity
content/entities/misc/非生物、非领域的杂项实体与投射物ElementalOrb、IceBlockProjectile
content/entities/ai/可复用的 AI 部件（Goal / MoveControl）goal/ApproachTargetGoal、control/WriggleMoveControl
render/entity/客户端渲染器（非 GeckoLib 的）ElementalOrbRenderer、IceBlockProjectileRenderer

2. 第一步：注册实体类型

所有实体类型集中在 content/entities/ModEntities.java 的 DeferredRegister<EntityType<?>> 里注册，不要在别处另开注册表。

public static final DeferredHolder<EntityType<?>, EntityType<IceBlockProjectile>> ICE_BLOCK =
        ENTITIES.register(
                "ice_block",
                () -> EntityType.Builder.<IceBlockProjectile>of(IceBlockProjectile::new, MobCategory.MISC)
                        .sized(0.9F, 0.9F)
                        .clientTrackingRange(8)
                        .updateInterval(2)
                        .build(ResourceKey.create(Registries.ENTITY_TYPE, Minegenshin.id("ice_block")))
        );
要点说明
注册名EntityType.Builder.build(ResourceKey) 与 ENTITIES.register(name, …) 两处必须一致，这是存档与数据包里的实体 ID
MobCategory生物用 MONSTER/CREATURE；投射物、领域、非生物一律用 MISC（不占刷怪名额，也不需要属性）
sized碰撞箱宽高。eyeHeight 决定视线与命中判定高度
clientTrackingRange / updateInterval同步距离与位置同步间隔（tick）。高速投射物给小的 updateInterval
注册入口在 Minegenshin.java 里由 ModEntities.register(modEventBus) 统一挂载

3. 第二步：写实体类

按"要不要 AI、是不是投射物"选择基类：

基类适用要覆写
Entity投射物、纯数据实体defineSynchedData、readAdditionalSaveData/addAdditionalSaveData、tick
PathfinderMob / Monster会走路的生物registerGoals、createAttributes；通常还要 customServerAiStep
AbstractArrow / 其它原版投射物能用原版飞行与命中逻辑时只做伤害与特效，不要重写飞行
Projectile自定义飞行轨迹的投射物shoot、onHit、tick
构造期陷阱：registerGoals() 在构造函数里被调用，此时字段还没初始化；Goal 里要用的值必须来自构造参数或静态数据，不要在 Goal 构造时读实例字段。

实体类骨架（以投射物为例，完整实现见 content/entities/misc/IceBlockProjectile.java）：

public class IceBlockProjectile extends Entity {
    private static final EntityDataAccessor<Boolean> DATA_CHARGING = SynchedEntityData.defineId(IceBlockProjectile.class, EntityDataSerializers.BOOLEAN);

    public IceBlockProjectile(EntityType<? extends IceBlockProjectile> type, Level level) { super(type, level); }

    @Override protected void defineSynchedData(SynchedEntityData.Builder builder) { /* 同步字段在这里声明 */ }
    @Override protected void readAdditionalSaveData(ValueInput input) { /* 存档读取 */ }
    @Override protected void addAdditionalSaveData(ValueOutput output) { /* 存档写入 */ }
    @Override public void tick() { /* 服务端推进 + 命中判定 */ }
}

4. 属性与生物类别

生物必须在 ModEntities.registerEntityAttributes 里注册属性，否则加载期会报 Entity minegenshin:xxx has no attributes：

private static void registerEntityAttributes(EntityAttributeCreationEvent event) {
    event.put(LARGE_CRYO_SLIME.get(), LargeCryoSlime.createAttributes().build());
}

属性表用 Monster.createMonsterAttributes() 或 Mob.createMobAttributes() 起手，再 add 生命/攻击/移速/护甲等——具体数值走本项目的属性系统（见技术文档"属性与效果"）。

5. 生成、刷怪与生成蛋

自然生成位置在 ModEntities.registerSpawnPlacements 里声明；本项目的怪物只在"入侵状态"下生成：

event.register(LARGE_CRYO_SLIME.get(), SpawnPlacementTypes.ON_GROUND,
        Heightmap.Types.MOTION_BLOCKING_NO_LEAVES,
        (type, level, spawnType, pos, random) ->
            level instanceof ServerLevel sl && TeyvatWorldInvasion.get(sl).isInvaded(),
        RegisterSpawnPlacementsEvent.Operation.REPLACE);

生成蛋走物品注册（core/system/registry/register），用 SpawnEggItem 绑定 ModEntities.XXX。

6. AI：Goal 还是 Brain

想要的效果用什么
近战追击、远程放技能、逃跑、开门、巡逻Goal（registerGoals + addGoal(优先级, new XxxGoal(...))）
多条状态机、要记忆/感知/日程的复杂怪物Brain + Behavior + Memory + Sensor
只想复用一套走法自定义 MoveControl/JumpControl，如 WriggleMoveControl

本项目现有怪物一律用 Goal（如 CryoSlimeShardGoal、CryoSlimeMistGoal、CryoSlimeSkillGoal）。写自定义 Goal 的模板、原版 Goal 全清单、标志位仲裁与优先级规则，见 实体 AI 深入指南。

7. 数据同步

需求做法
少量状态（是否蓄力、剩余时间、方块状态）SynchedEntityData.defineId + setData/getEntityData()，客户端自动可见
一方向客户端发事件（伤害飘字、特效指令）走 core/network 的 RPC（见 DamageIndicatorRpc）
玩家数据/角色数据不要放实体里，走附件系统（core/attachment + core/sync）
同步字段一旦发布就不能改类型或删改语义：它参与网络协议与存档兼容。改字段名/顺序要安排版本迁移。

8. 渲染与资源布局

客户端渲染器在 MinegenshinClient.registerEntityRenderers 里统一注册（@EventBusSubscriber(Dist.CLIENT)）：

event.registerEntityRenderer(ModEntities.ICE_BLOCK.get(), IceBlockProjectileRenderer::new);
渲染方式用在哪资源位置
GeckoLib 模型（GeoEntityRenderer + CategoryGeoModel）有动画的生物/召唤物assets/minegenshin/entity/<id>/<id>.json、.animation.json、.png
原版风格渲染器方块造型投射物、无骨骼模型的对象无模型文件，用原版方块/物品模型
GeckoLib 只扫自己的目录，本项目把实体资源统一放在 assets/minegenshin/entity/<id>/，由 CategoryGeoModel 与 AssetGeoCache 解析。 不要把 AssetGeoCache 注册成全局资源重载监听器：它一旦抛异常会让整个客户端资源重载失败，所有资源驱动的表现（动作、动画、贴图）一起失效。它在客户端 setup 时预热，并有"首次查询时同步扫一次"的兜底。

9. 投射物专章：照抄"冰块"这条完整链

IceBlockProjectile 是本项目最干净的投射物范例，全流程如下：

环节做法
创建静态工厂 create(level, caster, target, scale, chargeTicks)，由技能自己调用（如 CryoSlimeShardGoal）
实体类型ModEntities.ICE_BLOCK，MobCategory.MISC，尺寸 0.9×0.9
外观同步 BlockState，客户端用 IceBlockProjectileRenderer 复用原版方块渲染并自转
蓄力/缩放SynchedEntityData 同步蓄力进度与缩放，服务端决定发射时机
命中tick() 里做 AABB 检测，命中后造成伤害（走 attack 系统）并销毁
渲染注册MinegenshinClient.registerEntityRenderers 一行

11. 新增实体检查清单

  1. 在 ModEntities 注册 EntityType（名字与 ResourceKey 一致）
  2. 写实体类，覆写 defineSynchedData 与存档读写
  3. 是生物 → 在 registerEntityAttributes 注册属性；registerGoals 挂 AI
  4. 要自然生成 → 在 registerSpawnPlacements 里声明，并遵守"入侵状态才生成"的项目约定
  5. 客户端渲染器 + 在 MinegenshinClient.registerEntityRenderers 注册（GeckoLib 模型还要按 entity/<id>/ 放资源）
  6. 语言文件补 entity.minegenshin.<id>（zh_cn.json 与 en_us.json）
  7. 需要掉落 → 走 core/system/loot（EntityDeathDropHandler）或数据包战利品表
  8. 编译（批量改动后加 --rerun-tasks），进游戏用生成蛋或命令实测一次

12. 常见坑

现象原因与处理
加载期报 Entity xxx has no attributes生物类别忘了注册属性；投射物/领域用 MobCategory.MISC 就不会有这条
客户端看不见实体/没有模型渲染器没注册，或资源不在 entity/<id>/ 布局下，或 AssetGeoCache 未预热
动画不播 / 键名对不上GeckoLib 动画键与 .animation.json 里的名字不一致；见 AI 指南里 CategoryGeoModel 的解析失败提示
Goal 在构造时报空指针registerGoals() 在构造期调用，读不到实例字段
投射物位置抖动/命中判定偏移updateInterval 太大；配合 clientTrackingRange 调小
专用服务器崩溃（NoClassDefFoundError）公共侧代码引用了客户端类。实体/公共类里不要 import net.minecraft.client.* 或本项目的 client.*
