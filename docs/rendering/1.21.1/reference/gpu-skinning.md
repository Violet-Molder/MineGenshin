# 7. GPU 蒙皮与渲染性能

「为什么角色多了就掉帧」这个问题，答案在这章：先看成本长什么样，再看 1.21.1 上能做什么。

## 7.1 两条路：CPU 蒙皮与 GPU 蒙皮

骨骼动画的本质是「顶点跟着骨骼走」。有两种实现：

| | CPU 蒙皮 | GPU 蒙皮 |
| --- | --- | --- |
| 谁算顶点 | CPU：逐骨骼遍历、逐顶点做矩阵乘法 | GPU：顶点着色器里做 |
| 每帧传什么 | 变换后的顶点（可能几万个） | 骨骼矩阵（几十个 mat4） |
| GeckoLib 默认 | ✅ 走这条 | ❌ 不做 |
| 优点 | 实现简单、能和原版管线共存 | CPU 时间大幅下降 |
| 代价 | CPU 时间随顶点数线性涨 | 需要自定义管线/着色器，兼容性要自己管 |

## 7.2 CPU 路径的成本结构

GeckoLib 的默认路径每帧要做：

```text
每帧 / 每个模型实例：
  骨骼遍历（N 根骨骼 × 层级深度）
    → 每根骨骼算一次相对矩阵
      → 每个立方体的每个顶点做一次矩阵乘法 → 写进 VertexConsumer
```

成本 ≈ `骨骼数 × 顶点数 × 同屏实例数`。
所以「降帧」的两个杠杆是**减骨骼/减面**（模型侧）和**减实例**（玩法侧），
第三才是渲染侧的黑魔法。

## 7.3 1.21.1 上的现状

本项目 1.21.1 分支的几何接管**还没接**：

```java
// client/render/optimize/GeoRenderIntercept.java（1.21.1 分支）
public static boolean trySubmit(Object renderPassInfo, Object renderTasks, Object renderType) {
    return false;   // 本实现不自己提交任何几何
}
```

也就是说：1.21.1 的角色渲染走 **GeckoLib 默认 CPU 路径**。
26.2 那边才有「提交阶段接管 + GPU 蒙皮」的完整实现 —— 那套结论不能搬到 1.21.1。

## 7.4 1.21.1 上真正有效的优化

按收益从高到低：

1. **减骨骼、减面**（模型侧）。面数与骨骼数是乘数关系，改模型是唯一能改量级的手段。
2. **限制同屏实例数**。图鉴、摆件预览、召唤物这类「一时兴起就出来几十个」的场景最容易翻车；
   加一个距离剔除或数量上限，比调着色器有效得多。
3. **缓存每帧不变的东西**：`RenderType` 引用、`BakedGeoModel` 引用、光照值、贴图。
   每帧重新解析资源路径是纯浪费。
4. **同材质批量写**：同一 `RenderType` 的顶点连着写，减少状态切换（立即模式的状态切换是真的贵）。
5. **视锥与距离剔除**：`shouldRender` 里做粗筛。宁可少剔也别误剔（模型比碰撞箱大很多时容易被误剔）。
6. **动画速率与更新频率**：远处的实体可以降频更新动画（每 2 刻求值一次），视觉上几乎看不出来。

## 7.5 测量：先量再改

| 手段 | 看什么 |
| --- | --- |
| `F3` | 帧时间、实体数；先确认是 CPU 还是 GPU 瓶颈 |
| 关掉自己的模组特效 | 对比帧时间，确认是不是本模组的锅 |
| 项目内的 `FrameTimeStats` | 每个阶段的时间统计 |
| `RenderOptimizeStats` / `RenderOptimizeDebugEntry` | 优化路径的计数与耗时（1.21.1 上优化路径未开，统计仍可用） |
| Photon 编辑器 | 单独预览一个 `.fx` 的开销 |
| `LightPassTimer` / `LightDebug` | 动态光的耗时 |

判断方法：如果 `F3` 的帧时间在 CPU 侧、且与「模型数量」成正比 → CPU 蒙皮瓶颈；
如果与「像素/粒子面积」成正比 → GPU 瓶颈（Blend/Overdraw）。

## 7.6 常见误区

| 误区 | 事实 |
| --- | --- |
| 「换了自己的着色器就更快」 | 决定速度的是顶点数与状态切换，着色器本身通常不是瓶颈 |
| 「关掉光影就快」 | 光影影响的是 GPU 侧；CPU 蒙皮瓶颈关光影没用 |
| 「把模型拆小就能省」 | 骨骼层级变深反而更慢；要减的是**总数**与**顶点数** |
| 「缓存 `BakedGeoModel` 能省」 | 烘焙结果只在重载时变，缓存是好事；但缓存**自己算的顶点数组**通常更慢 |
| 「1.21.1 有 GPU 蒙皮，照 26.2 的配置开就行」 | 1.21.1 没有这套实现 |
